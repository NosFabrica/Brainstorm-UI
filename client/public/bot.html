BrainstormBot

If you found this address in your access logs, this page explains who we are, why we requested your page, and how to make it stop.

Brainstorm is an open-source Web-of-Trust client for nostr, operated by NosFabrica. When someone reads a note that contains a link, we fetch that page's OpenGraph tags so we can show them a preview card — a title, a description, a site name, and a thumbnail — instead of a bare URL.

The User-Agent

We send this User-Agent on every request, and never any other:

BrainstormBot/1.0 (+https://brainstorm.world/bot)

We do not send a User-Agent belonging to another company's fetcher. If a request claiming to be Googlebot, facebookexternalhit, Twitterbot, or Slackbot is hitting you, it is not us.

What we do

  • Fetch only what a person is looking at. Every request is triggered by a human opening a note that links to your page. We honour robots.txt. We do not crawl, we do not follow links out of the pages we fetch, and we hold no URL list to work through.
  • Fetch once, not once per reader. A successful result is cached for 24 hours and a failure for 5 minutes, so a link in a widely-read note costs you roughly one request a day from each instance we run, rather than one per viewer.
  • Read the head and stop. We stream the response and stop as soon as we have the <head>, subject to a floor of 8 KB — some sites put their metadata after a large inline block, so we do not cut before that. The whole read is capped at 512,000 bytes.
  • Give up quickly. 3 seconds per hop, 5 seconds overall, and at most three redirects.
  • Request HTML only. We send Accept: text/html,application/xhtml+xml, and a response that is not one of those two types is discarded unparsed.
  • Rate-limit ourselves. Requests are capped per calling IP address over a fixed window, using the address from our own proxy chain rather than anything the caller claims in a header.
  • Drop tracking parameters. utm_*, fbclid, gclid, msclkid and igshid are stripped before we request the page, so we do not forward a sharer's campaign identifiers to you.

The numbers above are what we run today. The redirect limit is fixed in the code; the timeouts, the size cap, the cache lifetime and the rate limits are deployment settings, so treat them as current values rather than as a contract. What does not change is the shape: user-triggered, cached, capped, and identified.

What we do not do

  • We do not log the URL that was fetched. It is not written by our request-logging layer at any log level — we hold tests that fail if it ever is. One honest caveat: the HTTP library underneath us names the host it connects to at DEBUG, which our production log level does not enable. The host, never the path or query.
  • We do not execute JavaScript, submit forms, or authenticate.
  • We do not store your page. Five short fields survive — title, description, image URL, site name, and the final URL after redirects — of which the title, description and site name are length-capped. Nothing else is kept, and only for the cache lifetime above.
  • We do not index you or resell anything derived from you.

robots.txt

We read your robots.txt and we honour it. A Disallow covering the page means we do not request that page at all — not that we fetch it and discard the result. We follow RFC 9309: our product token is BrainstormBot, the most specific group naming us wins over *, and where no rule matches we treat the path as allowed. If the file is missing we take that as permission; if it cannot be read at all, we treat that as a refusal until it can.

One deliberate exception: we ignore Crawl-delay. It is not part of RFC 9309, and the delays sites publish are measured in tens of seconds — unworkable for a fetch a reader is waiting on. We would rather name that here than quietly disregard it. What we do instead is ask for one page, once, and remember the answer for a day.

How to block us

The simplest way is robots.txt, which we obey:

User-agent: BrainstormBot
Disallow: /

Blocking by User-Agent works too — the token is stable and we will not change it to evade a block:

if ($http_user_agent ~* "BrainstormBot") { return 403; }   # nginx

A 403, 429, or 451 is fine by us; we cache the failure and move on. If you would rather we stopped without you having to configure anything, email us and we will stop fetching your host.
