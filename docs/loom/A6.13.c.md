# A6.13.c A guide topic on answering a find-me question

A story under A6.13, the interim search tool (NosFabrica/brainstorm-connector `docs/loom/A6.13.md`). This is its plan.

`brainstorm_search` (A6.13.b) runs one search in the box's language. A question like "restaurants in Funchal rated by podcasters I trust" is several searches and a join, and nothing tells an agent how to do that, or what to say when the data isn't there.

## What it adds

**In this repo:** `docs/search/find-me.md`, served by the Brainstorm connector as `ui/search/find-me`. It says how an agent:

1. breaks the question into the people, the things and the act that joins them;
2. finds the lists the words name: a Trusted List for a kind of person (kind 30392, `tl-tag-<observer>-<tagger>-<tag>`), a DList for a kind of thing (`tapestry_lists`), with the fallbacks when there is none;
3. writes each part as an ordinary search in the box's language, and puts the join in one search where the grammar allows it (`from:` many people, `to:` many things, `kind:`: fields AND, values OR);
4. joins the rest itself;
5. says who wrote or vouched for each result, gives brainstorm.world links, and says plainly what is missing.

It works the Funchal question through on the live relay, with what each step found on 2026-10-31.

**In the Brainstorm connector:** the map gains "Answering a find-me question, as an agent", and the tool's description and the connector's instructions name the topic. Working the example found two faults in `brainstorm_search`, fixed in the same pull request:

- `kind:` in the query was parsed and dropped. `buildFilters` takes its kinds from the caller, as the box narrows its tab's kinds by the typed one; the tool now narrows its `kinds` the same way.
- One event whose `created_at` is no calendar day made the whole answer throw. Its date is null now.

## Done when

`ui/search/find-me` is served by the connector, and the map points to it.
