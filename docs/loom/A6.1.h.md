# A6.1.h Export templateOf from the list module, and re-pin

A follow-up under A6.1, the Tapestry connector (nousclawds4/tapestry `docs/loom/A6.1.md`), found while building A6.1.f. This is its plan.

The connector's `tapestry_draft` runs `importIntoDraft` from the pinned list module (A6.1.a, `client/src/lib/listTools.ts`). It passes no existing URL templates, so every template an AI proposes comes back `new`, even when one of the same shape exists. List Management's Import passes the templates it has read, and `adoptTemplates` links to an existing template instead (`similarTemplates`).

The connector can't do the same today, because the module doesn't export:

- `templateOf`, which turns a URL Templates item into the `UrlTemplate` that `importIntoDraft` and `listAuthoringPrompt` take;
- where the templates are: the URL Templates concept, a role in `config/dictionary.config.json`.

## What it changes

**In this repo:**

- `listTools.ts` exports `templateOf` and `similarTemplates` from `lib/linkTemplates`, with the `UrlTemplate` type.
- It also exports `URL_TEMPLATES_LIST`, the `url-templates` role's coordinate, read from `config/dictionary.config.json` itself. `config/dictionary` reads the tag relays through `config/tagging`, which reads the env and the browser's storage, so the module doesn't import it.
- The build test checks that the built `templateOf` reads a URL Templates item as the source does. It also checks that `importIntoDraft` with existing templates gives the source's outcomes, an existing one included.

**In Loom (nousclawds4/loom):**

- `scripts/pin-lists.ts` re-pins the vendored build to this change's commit.
- `tapestry_draft` reads the URL Templates list's items from the relays (kinds 39999 and 9999, since A6.1.j), turns each into a template with `templateOf`, and passes them to `importIntoDraft`, as Import does. The draft then reports `templates.compared: true`.
- If no relay answers, the draft still comes back. It is not compared, and it says why.

## Done when

`tapestry_draft` reports `existing`, with the existing template, for a proposal that one already builds, and links the header to that template's id.
