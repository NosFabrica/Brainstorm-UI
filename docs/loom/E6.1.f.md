# E6.1.f Bring the eval runner up to date with the app

The spec for a follow-up of the labelled-set epic ([E6.1](E6.1.md)), found while running its stories.

## Problem

`scripts/search-eval/baseline.mjs` scores search the way the Top page shows it, so it has to follow what the page
does. It has fallen behind in two places.

- **The Dictionary.** A list's preview shows on the Top page only when its concept is in the Dictionary
  (`components/items/ListKindSearch.tsx`). Since #255 the app reads the Dictionary from the events that decide it
  (`lib/dictionaryConcepts.ts`): the house's taggings with the curator tag say who curates, and those curators' own
  self-pointing headers say what is in. The runner still asks for the old Demo Dictionary Concepts list through
  `views.conceptList`, which #255 removed from `config/dictionary.config.json`, so it finds nothing and marks Places,
  Books and GitHub Accounts "not on the Dictionary list". Every entry expecting one of them scores 0.
- **Multi-valued tags.** `propertyMatches` reads only the first tag of a name. Food and Drink Places items now carry
  every cuisine value as its own `cuisine` tag, so a cuisine filter misses a place whose matching value is not the
  first.

## For whom

Anyone reading the harness's numbers, and story E6.1.e, whose baseline rerun is meaningless until both are fixed.

## Done when

- The runner decides what is in the Dictionary as the app does: the curators from the house's curator taggings (a
  `polarity` below 0.5 disputes one), then the curators' newest kind-39998 headers that point at themselves, read
  from the tag hub where the app reads them. The house is found as the app finds it (the server's NIP-05 `_`), even
  when `--observer` runs the queries through someone else's network.
- A property filter matches any value of a tag the item carries more than once.
- Both are pure functions with tests that `npm test` runs.
- A run on E6.1.a's places entries shows Places again.

## Out of scope

Anything else the runner mirrors; reading Event Index items in the events band, which the Top page does not do
either; and the rerun itself (E6.1.e).
